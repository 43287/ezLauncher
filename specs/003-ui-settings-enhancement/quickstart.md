# Quickstart & Validation Guide: ui-settings-enhancement

本指南提供了一系列端到端的验证场景，用于确保 `ui-settings-enhancement` 重构阶段中所有功能和修复达到预期目标。

## Prerequisites

- Windows 10/11 操作系统。
- Node.js (v18+) 与 Rust 工具链就绪。
- 项目已通过 `npm run build` 和 `cargo clippy` 的静态检查。

## Validation Scenarios

### 1. 灾难恢复与防损机制验证 (FR-001, FR-003)

**目的**：验证 A/B 备份与恢复向导能否在文件损坏时拯救数据。

1. 关闭正在运行的 ezLaunch 应用。
2. 进入 `src-tauri/data/` 目录（或 `AppData/Roaming/...` 根据便携模式而定）。
3. 使用文本编辑器打开 `settings.json` 或 `apps.json`，随意删减大段文本以**人为破坏 JSON 格式**。
4. 运行应用 `npm run tauri dev`。
5. **预期结果**：应用不会静默启动一个空面板。屏幕中央必须弹出一个明显的“恢复向导”对话框，提示文件损坏，并提供一个【尝试从备份恢复】的按钮。
6. 点击恢复按钮。
7. **预期结果**：应用通过 `.bak` 文件成功回滚，之前的数据重现。

### 2. 左右侧停靠与宽度自适应验证 (FR-004, FR-005)

**目的**：验证定制化 UI 与窗口物理尺寸动态计算的联动性。

1. 启动应用。
2. 打开“设置”面板，找到并调整【网格列数】，例如从 `4` 修改为 `8`。
3. **预期结果**：整个应用窗口的宽度应立即、平滑地拉宽，以恰好容纳 8 列图标，不会出现横向滚动条或空白缝隙。
4. 在设置中找到【停靠方向】，将 `右侧` 切换为 `左侧`。
5. **预期结果**：侧边栏（Sidebar）立即从右边移动到左边。按下 `Esc` 隐藏应用，再按下 `Alt+Space` 唤醒应用。
6. **预期结果**：窗口的入场和退场动画方向应该完全反转，变为从屏幕**左边缘**滑入滑出。

### 3. IPC 性能拆分验证 (FR-008)

**目的**：验证拖拽操作的流畅度，确认 O(N) 性能瓶颈已被消除。

1. 准备一个包含至少 50 个应用的密集网格配置。
2. 启动应用，按住某一个应用图标并快速在其他图标间拖拽滑动，不要松手。
3. **预期结果**：拖拽过程保持 60fps 的绝对丝滑。
4. 松开图标完成位置调换。
5. **预期结果**：在接下来的一秒内，前端只触发了 `save_apps` 的 IPC 调用，没有触发 `save_settings`，且后台不会发生明显的主线程阻塞或掉帧。

### 4. 键盘二维漫游 (A11y) 验证 (FR-007)

**目的**：验证无障碍焦点切换的连贯性。

1. 启动应用，将鼠标移开。
2. 按下 `Tab` 键直到焦点落入网格区域的第一个图标上（会有蓝色高亮框）。
3. 按下 `ArrowRight`。
4. **预期结果**：焦点移动到同行右侧的相邻图标。
5. 按下 `ArrowDown`。
6. **预期结果**：焦点垂直向下移动到下一行的对应位置。
7. 按下 `Enter` 键。
8. **预期结果**：当前高亮的应用程序被成功拉起执行。
