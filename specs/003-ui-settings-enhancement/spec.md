## Clarifications

### Session 2026-06-20

- Q: 如何彻底解决 tertiary_defect_analysis_report 中指出的 1.1、2.1、5.1、6.1、7.1 的各项遗漏缺陷，并确保配置不再容易损坏？ → A: 将上述缺陷拆解并直接映射为功能需求（FR-002, FR-003, FR-008, FR-009）。为降低文件损坏可能，存储层 MUST 实现“写入时重命名（Write-Rename）”原子操作和“A/B 双重备份缓冲”机制。
- Q: "根据网格列数动态调整整个应用的宽度" 的具体计算逻辑应该是什么？ → A: 精确计算宽度（窗口宽度 = (列数 * 单个网格宽度) + Sidebar宽度 + Padding。超出屏幕最大宽度时截断）。
- Q: 当更改为"左侧停靠"时，窗口呼出/隐藏的动画方向是否也需要反转？ → A: 从停靠侧滑出（如左侧停靠则从左侧边缘滑入/滑出）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 修复高危缺陷与架构瓶颈 (Priority: P1)

作为一名终端用户，我希望应用的配置文件在遇到损坏或跨设备无法解密时，能够安全地提示我恢复，而不是静默丢失所有数据。同时，我希望频繁的交互操作（如拖拽调整应用顺序）不会引起系统明显的卡顿，且快速切换配置不会导致设置失效。

**Why this priority**: 解决了导致数据丢失（Data Loss）和潜在数据分叉的 P0 级别安全和稳定性缺陷，以及 P1 级别可能引发主线程阻塞的性能瓶颈。

**Independent Test**: 
- 能够通过故意破坏配置文件或提供错误的加密密钥，独立验证系统是否正确抛出并捕获错误，而非静默重置。
- 在多次高频的网格排序操作后，确认不会触发全量配置写入导致的 UI 卡顿。

**Acceptance Scenarios**:

1. **Given** 用户的 `settings.json` 被损坏或无法被当前设备的密钥解密，**When** 用户启动应用，**Then** 应用必须弹出恢复向导阻断启动，提供“重置配置”按钮（点击后自动备份损坏文件并生成全新配置以恢复使用），并**绝不**静默用 `{}` 覆盖原始文件。
2. **Given** 用户在系统设置中快速切换通用选项并在界面上执行操作，**When** 触发 500ms 防抖同步，**Then** `useDataStore` 作为唯一状态源，能够确保配置持久化无分叉竞态。
3. **Given** 包含数百个应用的大型配置，**When** 拖拽调整一个应用的顺序，**Then** 不会触发整个通用配置设置的全量序列化与落盘，确保操作流畅。

---

### User Story 2 - 个性化布局定制 (Priority: P2)

作为一名终端用户，我希望能够根据我的屏幕使用习惯，自由选择启动器是贴靠在屏幕左侧还是右侧。并且，我希望能够调整主界面显示的网格列数，而整个应用的宽度应当根据我设置的列数自动适配。

**Why this priority**: 满足了用户对桌面工具强烈的定制化需求，同时落实了配置项中尚未生效的“网格列数”设置。

**Independent Test**: 可以在设置界面中独立切换左右停靠和修改列数，立刻看到主窗口位置和尺寸的变化，无需依赖其它功能。

**Acceptance Scenarios**:

1. **Given** 系统默认为右停靠，**When** 用户打开设置将“侧边停靠”改为“左侧”，**Then** 整个应用的侧边分类栏（Sidebar）应移动至左边缘，且窗口动画反转为从屏幕左侧边缘滑入/滑出，贴边逻辑同步反转。
2. **Given** 默认网格列数为 4，**When** 用户在设置中将其修改为 6，**Then** 应用主窗口宽度应精确计算并自动拉宽（宽度 = 6 * 单个网格宽度 + Sidebar宽度 + Padding），而不会出现横向滚动条或图标重叠。
3. **Given** 左侧分类栏，**When** 鼠标悬浮在侧边栏上方，**Then** 依然会出现 "添加分类" 的 Tooltip 提醒（根据用户最新指令，撤销了移除操作，恢复了悬浮出现 `+` 号的效果）。

---

### User Story 3 - 键盘无障碍漫游 (Priority: P3)

作为一名 Power User 或无障碍需求者，我希望能够在不使用鼠标的情况下，仅通过键盘的方向键在网格中自由穿梭并回车启动应用。

**Why this priority**: 修复了上一轮报告中指出的 P1 级 A11y（无障碍）缺陷，对于重度键盘用户至关重要，但对普通鼠标用户影响较小。

**Independent Test**: 可以不触碰鼠标，仅通过 Tab 和方向键在网格应用间导航，并使用 Enter 键启动。

**Acceptance Scenarios**:

1. **Given** 焦点在网格区域内，**When** 按下 `ArrowRight`，**Then** 焦点应移动到当前图标右侧的相邻图标上。
2. **Given** 焦点位于某行的末尾图标，**When** 按下 `ArrowDown`，**Then** 焦点应移动到正下方的图标。
3. **Given** 使用键盘聚焦到某个图标，**When** 按下 `Enter`，**Then** 对应的应用程序应该被拉起。

---

### Edge Cases

- 当用户设置了极大的网格列数（如 20列）导致应用宽度超出屏幕总宽度时，系统该如何处理？（预期：限制最大列数或强制限制最大宽度）。
- 当配置损坏时，如何确保在恢复向导完成前，前端的防抖写回机制（`useStoreSync`）绝对不会被触发？
- 左/右停靠切换时，与 Tauri 窗口拖拽调整（`data-tauri-drag-region`）以及出场动画的冲突处理。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 区分解析失败与文件不存在。当且仅当文件不存在时可以初始化新配置；如果文件存在但解密或解析失败，系统 MUST 阻断正常启动流程，提供包含“重置配置”选项的恢复界面。
- **FR-002**: 前端架构 MUST 移除 `useSettings` 中的全量 React Context 数据副本，所有的配置读写必须直接对接 `useDataStore`。
- **FR-003**: 存储层 MUST 进行职责拆分，将文件 I/O、加解密逻辑解耦，并引入“写入时重命名”原子操作机制防止文件损坏。
- **FR-004**: 系统 MUST 增加 "左/右停靠" 的配置项（默认值为右），并且侧边分类栏（Sidebar）的位置以及窗口进出动画方向 MUST 与停靠方向的边缘保持一致。
- **FR-005**: 系统的整体窗口宽度 MUST 根据设置中的“网格列数”进行精确计算并动态适配（窗口宽度 = (列数 * 单个网格宽度) + Sidebar宽度 + Padding）。
- **FR-007**: 应用网格（AppGrid）MUST 支持二维的键盘方向键导航（Roving Tabindex），支持 `ArrowUp/Down/Left/Right` 及 `Enter` 操作。
- **FR-008**: (对应 1.1) IPC 通信 MUST 采用增量同步或拆分配置表（如 settings.json 与 apps.json 分离落盘），避免 O(N) 级别的全量序列化导致跨层高耦合与粒度过粗。
- **FR-009**: (对应 6.1/7.1) 前端 MUST 引入 Zod/Yup 等 Schema 校验库，替代冗余的 `any` 强转与过度防御性代码；后端 Rust MUST 抛出具体错误枚举（如 `ServiceError::ParseError`），严禁使用 `unwrap_or` 掩盖底层错误。

### Key Entities

- **SettingsConfig**: 包含通用设置属性（如网格列数、停靠方向、自启状态等）的轻量级实体。
- **AppList**: 包含用户添加的所有启动器快捷方式的重量级数据集合。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在解密失败测试用例中，原始配置文件的哈希值在应用启动/关闭后保持 100% 不变。
- **SC-002**: 在 100 个应用图标的网格中进行拖拽排序，主线程阻塞时间 < 16ms（保证 60fps 的流畅度）。
- **SC-003**: 设置中的“网格列数”修改后，应用界面能实时无缝调整宽度，图标排列符合设定的列数。
- **SC-004**: 可在完全断开鼠标连接的情况下，使用键盘完成“呼出应用 -> 方向键定位 -> 回车启动”的完整核心工作流。

## Assumptions

- 假设由于左右停靠涉及操作系统的屏幕边缘，Tauri 窗口初始化的位置计算算法需要进行相应的对称调整。
- 假设“网格列数”合理的最大值为 12（以防超出常规带鱼屏宽度），最小值为 1。
- 假设灾难恢复仅需要提示并阻断覆盖，不强制要求自动通过网络或历史记录进行完美修复（保留 `.bak` 即可）。
