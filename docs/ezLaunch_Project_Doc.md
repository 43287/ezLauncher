## 2. 项目概览
- **目的**：简述项目的背景、核心目标及解决的痛点。
- **项目背景**：在日常 Windows 开发和办公环境中，频繁打开文件、应用和执行特定脚本会导致效率降低。现有的启动器往往资源占用较高或启动速度不佳。
- **核心目标**：利用 Tauri 和 Rust 打造一款轻量级、常驻后台、极速响应的快捷启动器，提供极简的交互界面。
- **预期价值**：极大提升 Windows 用户的键盘操作效率，降低高频工具调用的时间成本，提供快速流畅的用户体验。
- **验收标准/交付物**：清晰的项目描述与目标定义。

## 3. 范围定义 (v0.0.1 核心需求)
- **目的**：明确项目在 0.0.1 版本需要实现的具体功能模块，确保功能的完整性、模块化和解耦设计。
- **包含范围内（In Scope）**：
    - **1. 设置界面与通用项引擎**：
        - 实现独立的设置悬浮窗。
        - 将设置类别、具体设置项与 UI 彻底解耦。
        - 为每个设置项提供通用的数据结构配置（例如：`{ "desc": "滚轮反转", "type": "switch", "value": [0, 1] }`），UI 会根据数据类型自动渲染为开关、数字框、输入框等对应控件。
    - **2. 抽屉式容器与多类型 Item**：
        - 主界面抽屉作为容器，收纳名为 `Item` 的数据。
        - 支持右键添加或直接拖拽添加 Item。
        - 支持多种 Item 类型：可执行程序、链接、系统程序、脚本、pwsh/cmd 命令、系统设置等。
        - **格式组件**：特殊的排序与布局 Item（如横向/纵向分隔符），可重命名，用于在其它 Item 周围进行排版分隔。
        - 支持左键拖拽手动对 Item 进行重新排序。
        - 支持对 Item 进行右键设置（例如：添加启动参数、配置管理员启动）。
    - **3. 右键菜单系统 (Context Menu)**：
        - Item 级别：右键菜单支持“删除”、“设置”等管理操作。
        - Tab 栏级别：左侧纵向 Tab 栏支持右键操作；顶部横向 Tab 栏无需右键菜单。
    - **4. 状态与配置持久化**：
        - 需要持久化保存所有的应用信息，包括全局设置数据以及每个 Tab 页面存放的 Item 数据和设置选项。
        - 程序初始化时需自动加载恢复这些数据。
    - **5. 复合 Tab 导航系统**：
        - 左侧纵列 Tab：在空白处双击可创建新 Tab；支持拖动重排 Tab 的顺序。
        - 顶部横向 Tab：作为当前左侧分类下的子分类，同样支持对应的内容隔离。
- **包含范围外（Out of Scope）**：
    - 云端数据同步与备份。
    - 跨平台支持（首发仅针对 Windows 系统）。
    - 复杂的多媒体播放功能。
- **验收标准/交付物**：范围边界清晰，所有要求的新功能均有对应实现。

## 4. 需求规范
- **目的**：详细列出系统功能与非功能需求。必须附带可量化的指标、交互细节和UI/UX合规要求。
- **功能需求**：
    - **全局唤醒**：通过全局快捷键（默认 `Alt + Space`）唤醒输入界面。支持焦点自动切换到搜索框。
    - **文件拖放**：支持将文件或文件夹拖放至唤醒窗口。拖放期间必须禁用文本选择，并在拖动元素上使用 `inert` 属性，快速打开或复制路径。
    - **后台常驻**：应用启动后自动常驻后台系统托盘，关闭主窗口不退出进程。支持右键菜单（退出、设置）。
    - **本地搜索**：支持拼音首字母和关键字搜索本地应用与文件。
- **非功能需求**：
    - **性能指标**：冷启动时间 < 200ms；全局快捷键唤醒响应时间 < 50ms；后台常驻内存持续 < 30MB。
    - **无障碍体验 (A11y)**：
        - 所有交互元素必须支持键盘事件 (`onKeyDown`/`onKeyUp`)。
        - 所有图标按钮需带有 `aria-label`。装饰性图标需包含 `aria-hidden="true"`。
        - 列表滚动、异步更新结果需使用 `aria-live="polite"`。
    - **焦点管理 (Focus States)**：
        - 交互元素需有清晰的可见焦点，如 `focus-visible:ring-2`。禁止使用 `outline-none` 而无焦点替代方案。优先使用 `:focus-visible` 而非 `:focus`。
    - **动画规范 (Animation)**：
        - 必须响应 `prefers-reduced-motion`（提供无动画版本或禁用动画）。
        - 仅对 `transform` 和 `opacity` 进行动画处理。禁止使用 `transition: all`，必须明确列出属性。
    - **语义化 (Semantic HTML)**：
        - 严格使用语义化标签（如 `<button>` 处理动作，而非 `<div onClick>`）。
        - 文本长内容需正确处理截断（使用 `truncate` 或 `line-clamp`）。
- **验收标准/交付物**：所有的需求点均可通过自动化测试验证，并在静态代码分析中符合 A11y 规则。

## 5. 架构设计
- **目的**：基于 Rust UI Architecture 的四层架构（领域分离）与 Web Design Guidelines，定义从前端到后端的完整结构、IPC 签名与 UI 代码规范。
- **四层架构 (Four-Layer Architecture)**：
    1. **UI Layer (前端/视图层)**：基于 React + TailwindCSS 构建。负责渲染、焦点管理、动画和事件收集。
        - **目录**：`src/components/` (复用组件), `src/views/` (高层视图)。
        - **模式**：Container-Presenter 模式。容器负责调用 IPC 和状态管理，Presenter 负责纯渲染。
    2. **Application Layer (应用/状态层)**：Rust 后端负责状态协调、系统 API 交互的封装，或前端通过 React Hook 管理的状态。
        - **目录 (Rust)**：`src-tauri/src/models/` (应用状态) 和 `src-tauri/src/commands.rs` (IPC 指令)。
    3. **Service Layer (服务层)**：外部集成，如文件系统 I/O、快捷键注册、托盘创建。
        - **目录 (Rust)**：`src-tauri/src/services/` (如 `file_service.rs`, `shortcut_service.rs`)。
    4. **Domain Layer (领域层)**：纯粹的业务逻辑与数据结构，完全脱离框架和 UI 依赖。
        - **目录 (Rust)**：`src-tauri/src/domain/` (如 `app_entity.rs`, `search_logic.rs`)。
- **IPC 签名规范 (Tauri Invoke)**：
    - `plugin:search|query_apps`: `(query: string) -> Promise<AppResult[]>`
    - `plugin:window|hide_window`: `() -> Promise<void>`
    - `plugin:file|handle_drop`: `(paths: string[]) -> Promise<void>`
    - *注：后端统一返回标准化的 Result 格式。前端需正确处理 loading 状态及 Error 提示。*
- **UI 代码规范 (Web Interface Guidelines)**：
    - **表单与输入**：禁用不需要的拼写检查 `spellCheck={false}`，避免密码管理器误触 `autocomplete="off"`。输入框需响应式处理。
    - **排版与内容**：加载状态使用 `…`（如 `Loading…`）。按钮标签需首字母大写（Title Case），如 `Search Apps`。
    - **暗黑模式**：HTML 根节点使用 `color-scheme: dark`，原生控件适配 Windows 深色模式。
    - **性能与渲染**：超过 50 项的搜索结果必须使用虚拟化列表。不使用 `getBoundingClientRect` 等在渲染周期内的布局读取。
- **验收标准/交付物**：确立严格的目录结构和 IPC 签名清单，AI 可根据路径和签名直接生成代码。

## 6. 实施任务
- **目的**：将需求转化为 AI 可直接读取并编写代码的细颗粒度任务。
- **阶段 1：项目骨架与四层架构初始化**
    - **任务 1.1**：执行 `npm create tauri-app@latest ezLaunch -- --template react-ts` 创建基础项目。
    - **任务 1.2**：在 `src-tauri/src` 下创建 `domain`, `services`, `models`, `commands` 文件夹。
    - **任务 1.3**：配置 TailwindCSS。在 `tailwind.config.js` 增加 `dark: "class"` 和焦点环配色。
- **阶段 2：领域层与服务层开发 (Rust 端)**
    - **任务 2.1**：在 `src-tauri/src/domain/app_entity.rs` 中定义 `AppResult` 结构体，包含 `id`, `name`, `path`, `icon`。
    - **任务 2.2**：在 `src-tauri/src/services/shortcut_service.rs` 中实现 `Alt+Space` 注册。使用 Tauri 插件机制。
    - **任务 2.3**：在 `src-tauri/src/services/file_service.rs` 中实现路径解析和启动执行逻辑。
- **阶段 3：IPC 接口与状态管理集成**
    - **任务 3.1**：在 `src-tauri/src/commands.rs` 暴露 `search_apps`, `execute_app` 指令，并注册到 `main.rs`。
    - **任务 3.2**：在 `src/hooks/useSearch.ts` 封装调用逻辑，管理 `isLoading`, `error`, `results`。
- **阶段 4：UI 层严格遵守规范开发 (React 端)**
    - **任务 4.1**：在 `src/components/SearchInput.tsx` 开发输入框。必须包含 `autoFocus`（桌面端合理场景），`spellCheck={false}`，并使用 `focus-visible:ring-2`。
    - **任务 4.2**：在 `src/components/ResultList.tsx` 开发结果列表。必须实现虚拟滚动，添加 `aria-live="polite"` 播报结果数量，确保支持上下方向键导航。
    - **任务 4.3**：在 `src/components/DropZone.tsx` 处理拖放事件，拖放时触发视觉反馈（仅使用 `opacity`/`transform` 动画并遵守 `prefers-reduced-motion`）。
- **验收标准/交付物**：每完成一个任务即可运行 `npm run tauri dev` 和 `cargo clippy` 验证，无警告且满足 A11y 审查。
